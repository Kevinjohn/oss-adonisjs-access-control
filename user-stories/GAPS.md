# Decision gaps

The authoritative [build specification](../docs/maintainers/design/spec-access-control.md) and current guides were reconciled against source for role rules, membership transactions, scope checks, callbacks and client payload. No unresolved decision/implementation mismatch was identified in this catalogue scope. The following retained boundaries are explicit contracts, not open gaps.

| Boundary                                 | Agreed contract                                                                                                                                                                                                   | Current implementation                                                                                                                                 | Catalogue treatment                                                                                    |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Effective identity and scoped permission | [Bouncer guide](../docs/guide/bouncer.md) requires Account Kit managed-account/admission middleware before scope middleware where credential/activation/admission checks matter; host owns record-level policies. | Scope middleware resolves `ctx.auth.user`, checks active membership; generated abilities evaluate its configured role.                                 | US-ACCESS-02 traces effective account to route check; it does not assign record policy to the package. |
| Trusted membership operations            | [Membership guide](../docs/guide/memberships.md) says actorless methods must not be exposed directly to request input.                                                                                            | `grant`, `createFirstMember`, `acceptInvitation`, `prepareAccountDeletion` and `removeAllForScope` trust host/callback context and caller transaction. | US-ACCESS-10, 13–15, 18, 20–21 and 25 state each trust boundary.                                       |
| Identity-wide authorization timing       | [Rules guide](../docs/guide/rules.md#who-may-administer-an-identity) says check all scopes and run immediately before the Kit operation; it does not make that separate operation atomic.                         | `assertCanAdministerIdentity` checks maps under locks, then returns to caller.                                                                         | US-ACCESS-11 preserves this limited guarantee.                                                         |
| Client payload                           | [Client guide](../docs/guide/client.md) defines presentation data, while server still enforces authorization.                                                                                                     | Active membership yields `scopeId`, `role`, `permissions`, `assignableRoles`; no membership/suspended returns null.                                    | US-ACCESS-12 records exact payload and server boundary.                                                |
| Configuration and migration              | [Setup guide](../docs/guide/setup.md) requires Account Kit config and `--scope-table`; lists optional table/key flags and manual integration steps.                                                               | `configure` checks prerequisites, skips existing files, publishes migrations and prints code changes for the host.                                     | US-ACCESS-14 describes actual required and optional inputs.                                            |
| Adoption                                 | [Adoption guide](../docs/guide/adopting.md) requires app-owned row copy, reconciliation and cutover; package never reads old table.                                                                               | Package uses configured memberships table after switch.                                                                                                | US-ACCESS-15 records operator-owned migration; no automatic arbitrary data mapping is claimed.         |
